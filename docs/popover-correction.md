# 菜单栏浮层与原型还原

## 问题与实现

普通左键曾显示系统菜单，未进入统计浮层。原实现同时给状态栏按钮挂载系统菜单和处理自定义点击，即使设置关闭左键菜单，仍出现用户报告的结果。尚未捕获旧版原生事件，不能认定为某个系统版本或依赖库的已证实缺陷。

状态栏按钮不再绑定常驻菜单：左键按下记录展开/收起意图，释放后执行；右键释放后通过 Tauri 的原生上下文菜单入口显式弹出菜单。浮层失焦隐藏；将刚发生的失焦与同次菜单栏点击关联，避免按下导致失焦后释放又展开。菜单中的详情、设置、退出行为保持不变。

浮层按托盘所在屏幕的工作区和缩放定位，宽 500、高不超过 780，保留负坐标屏幕原点。内容超出时滚动，标题和详情入口固定。设置窗口默认 820 × 790，恢复顶部通用/数据来源页签、品牌介绍、分段指标与主题选择、启动说明和分区。浮层恢复大数字、两张分布图的分位数注释及两行最近动态。

## 契约变更与影响

| 契约 | 变更与兼容性 |
| --- | --- |
| IPC 接口 | 无变化；现有 v1 命令、DTO 与窗口定向导航事件继续兼容 |
| 内部交互协议 | 左右键入口分离，按下/释放锁定同一次意图；窗口坐标按当前屏幕工作区计算；不改变统计算法或日志归并协议 |
| 数据库结构 | DDL：无变化 |
| 持久化数据 | 无变化；统计数据库、来源配置、历史记录和设置 revision 原样使用，无迁移、失效或重算 |
| 消费方 | 无需升级外部工具；应用前后端作为同一安装包更新 |

`RESONA_WINDOW_TRACE=1` 是可选本地诊断开关，仅向标准错误记录鼠标按钮、窗口位置/可见性/焦点和操作结果，不记录会话、指标、来源路径，不默认写文件或上传。

## 上线步骤

1. 发布前执行前端格式、ESLint、类型检查、交互测试，Rust 格式、Clippy、工作区测试和版本/SQL/桌面契约检查。
2. 将合成数据截图与 04、07、08 原型去除桌面装饰后按内容宽度对照；同时验证 500 × 780 的滚动与固定入口。
3. 构建应用与 DMG；验证签名和 DMG。退出已运行实例，替换本地应用并重启，核对安装文件与构建文件哈希。
4. 固定 Case：普通左键展开，再次左键收起；点击外部和 Escape 收起；右键仅显示菜单且各项有效；浮层详情/设置切换后窗口不串页；时间范围作用于双分布；小屏与外接屏不超出工作区。
5. 数据 backfill、重算、恢复自动任务均不适用。应用启动后继续既有本地增量采集。
6. 观测原生事件和可见状态，原生点击未验收不得标记交付完成；回滚入口为前一个应用构建，数据无需回退。公开签名发布仍遵循既有发布流程，不以 ad-hoc 包替代公证版。
